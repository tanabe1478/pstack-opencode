## What changed in this OpenCode port

The port keeps the upstream skill bodies and rewrites the integration layer for OpenCode. Changes are editorial: Claude Code and Cursor primitives are replaced with OpenCode tools, commands, agents, and plugin hooks.

Summary of structural changes:

- The plugin now lives at the repository root instead of `plugins/pstack/`. Skills are in `skills/`, subagents in `agents/`, and slash commands in `commands/`.
- `plugins/pstack.ts` is an OpenCode plugin that reads `pstack-models.md` and applies role models to the pstack subagents. It also injects the routing mandate from `hooks/session-start.md` through the `context` hook.
- Each public skill has a matching `commands/<name>.md`, so it can be invoked as `/<name>`. The `principle-*` skills are marked `metadata.opencode/autoinvoke: false` and have no commands.
- `agents/` adds 17 OpenCode-specific role and panel agents so that role-based model routing works without a `model` field on the `subagent` tool. The four upstream agents are preserved with OpenCode frontmatter and tool permissions.
- `skills/poteto-mode/references/opencode-tools.md` maps Claude Code and Cursor primitives to OpenCode tools, agents, models, and paths. Skill entry points link to it where behavior differs.
- `install.sh` and `uninstall.sh` install by symlink (or copy) into the global OpenCode config directory or a project's `.opencode/`.
- Claude Code hook and marketplace metadata (`.claude-plugin/`, `.codex-plugin/`, `.agents/`, `hooks/hooks.json`, `CHANGES.md`, and `tools/`) are not part of this port.

Skill bodies have been edited to replace Cursor- and Claude Code-specific tool names, agent names, model names, and paths with their OpenCode equivalents. All upstream copyright notices in source files (where present) are preserved.
